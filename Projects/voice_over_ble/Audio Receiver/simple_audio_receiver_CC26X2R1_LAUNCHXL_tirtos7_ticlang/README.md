# Voice over BLE — Audio Test Receiver (CC26X2R1)

BLE central receiver for validating the Voice over BLE audio pipeline. Connects to the audio transmitter (CC2340R53), receives compressed audio frames over GATT notifications, decodes them in real-time, and outputs PCM audio via I2S to an external audio codec.

```
[CC2340R53 Transmitter] --BLE--> [CC26X2R1 Receiver] --I2S--> [CC3200AUDBOOST Audio Boosterpack] ---> [Speaker / Headphones] --USB--> [PC Audio Recording Tool]
```

## Hardware Requirements

### CC3200AUDBOOST Boosterpack

This project requires the [CC3200AUDBOOST Audio Boosterpack](https://www.ti.com/tool/CC3200AUDBOOST) mounted on the CC26X2R1 LaunchPad.

The boosterpack carries a **TLV320AIC3254** stereo audio codec chip, which provides:
- I2S audio interface for receiving decoded PCM from the CC2642R1.
- DAC output to drive headphones or a speaker.
- I2C control interface for codec configuration (sample rate, volume, routing).

The CC2642R1 has no on-chip DAC capable of audio output. The TLV320AIC3254 is required to convert the decoded PCM stream to an analog audio signal.

**Alternative hardware:** The CC3200AUDBOOST can be replaced by any audio interface that:
- Accepts I2S input at 16 kHz, 16-bit mono (or 48 kHz with `USE_BW_24KHz`).
- Provides DAC or line output.
- Is controlled via I2C or has no configuration requirement.

## Features

### BLE Central

- Scans continuously for BLE peripherals advertising TI manufacturer data (ID `0x000D`, signature `0xC0 0xFF 0xEE`).
- Connects automatically when the target transmitter is found (max 1 concurrent connection).
- Performs GATT service discovery after connection with a 1-second settle delay.
- Enables notifications on the DataIn characteristic (`0xC0C1`) to begin receiving audio.
- Connection interval: 7.5 ms (matches transmitter streaming parameters).
- Max PDU size: 255 bytes.

### Audio Decoding and Playback

Received compressed frames are decoded in real-time and fed to the I2S output:

**ADPCM (default):**
- IMA ADPCM algorithm (IMA specification §6).
- Each encoded frame: 16 bytes → 32 PCM samples (16-bit).
- Compression ratio: 4:1.
- Decoder maintains step index and predicted value across frames for continuous streams.
- 4-byte frame header (predicted value + step index) is consumed for state recovery.

**mSBC (optional):**
- Modified Sub-Band Codec, 57 bytes → 120 PCM samples.
- Compression ratio: ~2.7:1.
- Higher quality than ADPCM; useful when the transmitter is configured for mSBC.

**I2S Output:**
- Decoded PCM buffered in a 16-frame deep queue before I2S write.
- Sample rate: 16 kHz (default) or 48 kHz (with `USE_BW_24KHz`).
- Bit depth: 16-bit PCM, mono.
- I2S master clock generated by GPTM3 on-chip timer.
- Estimated pipeline latency: ~32 ms at 16 kHz with ADPCM (16 frames × 32 samples / 16000).

### LED Status

| LED | GPIO | State |
|-----|------|-------|
| Red | GPIO 6 (bp.39) | Scanning / unconnected |
| Green | GPIO 7 (bp.40) | Connected and streaming |

### Debug UART

- Baud rate: 3 Mbps via XDS110 USB channel.
- Accumulates 25 decoded frames per UART write for logging and PC-side capture.

## BLE GATT Profile

The receiver subscribes to the Audio Stream service on the transmitter.

| Characteristic | UUID | Role | Size | Description |
|----------------|------|------|------|-------------|
| DataIn | `0xC0C1` | Notify (subscribe) | 255 bytes | Transmitter → Receiver: compressed audio frames. One frame per notification. |
| DataOut | `0xC0C2` | Write No Rsp | 255 bytes | Receiver → Transmitter: control commands (start/stop streaming). |

Service UUID: `0xC0C0`

## Build Configuration

Set these symbols in **Project Properties → Build → Compiler → Predefined Symbols**.

| Symbol | Options | Notes |
|--------|---------|-------|
| Codec | `USE_ADPCM_CODEC` or `USE_MSBC_CODEC` | Must match transmitter codec selection |
| Sample rate | `USE_BW_24KHz` | Enables 48 kHz output; omit for 16 kHz |

Default (as shipped): `USE_ADPCM_CODEC` at 16 kHz.

## Developing with this Reference Design

### Project Structure

```
Application/
  simple_serial_socket_client.c/h  — BLE central task: scan, connect, GATT discovery
  simple_stream_profile_client.c/h — Audio Stream GATT client (subscribe, receive frames)
  simple_service_discovery.c/h     — Generic GATT service/characteristic discovery
  audio_player.c/h                 — Codec dispatch, PCM buffering, I2S write
  adpcm/Codec1.c/h                 — IMA ADPCM decoder
  sbc/Codec2.c/h + sbc*/           — mSBC decoder
AudioHAL/
  AudioHAL.c/h                     — Audio output API (open, write, close)
  AudioHAL_I2C.c/h                 — I2C codec register writes
  AudioHALCodec.c/h                — Codec-agnostic initialization
  TLV320AIC3254.c/h                — TLV320AIC3254 register map and configuration
  MCLKCC26XX.c/h                   — On-chip master clock generation (GPTM3)
```

### Changing the Codec

Switch `USE_ADPCM_CODEC` ↔ `USE_MSBC_CODEC` in compiler defines. The codec must match the transmitter. Codec selection is resolved at compile time in `Application/audio_player.c`.

### Replacing the Audio Output Hardware

1. Replace `AudioHAL/TLV320AIC3254.c` with a driver for the new codec chip.
2. Update `AudioHAL/AudioHALCodec.c` to call the new init/configuration functions.
3. Update I2C address and register sequences to match the new device.
4. Verify I2S pin assignments in SysConfig match the new hardware.
